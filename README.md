# multi-model-cli

Подключает **Codex (OpenAI)**, **Grok Build (xAI)** и **Antigravity CLI (Google)** к
Claude Code как субагентов. Можно спросить второе мнение, а можно отдать настоящую
работу: разобрать сорок файлов, переписать модуль, собрать ресёрч.

> Содержимое на русском: комментарии в коде, скиллы и документация.
> *Content is in Russian - code comments, skills and docs.*

Обвязок над CLI хватает и без этой. Здесь отличие одно: **границы держит ядро, а не
обещание модели вести себя прилично.** Без флага `-w` модель физически не запишет ни
одного файла. С `-w` правки идут только внутрь каталога, который вы назвали явно.
Я это проверял не чтением документации, а попытками обойти запрет: через инструмент
правки, через шелл, через Python. Все три упёрлись в «operation not permitted».

---

## Что внутри

```
scripts/     три обёртки с одинаковым интерфейсом + Seatbelt-профиль для Antigravity
agents/      определения субагентов Claude Code
skills/      delegate (делегирование работы) и second-opinion (второе мнение)
docs/        грабли, собранные при сборке
```

## Требования

- **macOS.** Границы для Antigravity держатся на Seatbelt (`sandbox-exec`). На Linux
  без замены профиля работать не будет.
- Штатный **bash 3.2**. Код написан под него намеренно, без синтаксиса bash 4+.
- Установленные и авторизованные CLI. Нужен не каждый, можно взять любой один:
  - [Codex](https://developers.openai.com/codex): `npm i -g @openai/codex`
  - [Grok Build](https://x.ai/news/grok-build-cli): `curl -fsSL https://x.ai/cli/install.sh | bash`
  - [Antigravity CLI](https://antigravity.google/docs/cli/overview/): `curl -fsSL https://antigravity.google/cli/install.sh | bash`

## Установка

```bash
git clone https://github.com/snjrusmn/multi-model-cli.git
cd multi-model-cli
./install.sh
```

`install.sh` расставляет симлинки в `~/.claude/{scripts,agents,skills}`. Ничего не
затирает молча: наткнётся на существующий файл - скажет и пропустит.

## Использование

Интерфейс у всех трёх одинаковый:

```bash
~/.claude/scripts/ask-codex.sh  [-e УСИЛИЕ] [-m МОДЕЛЬ] [-t СЕК] [-d DIR] [-f ПУТЬ]... [-s СКИЛЛ]... [-w] "промпт"
~/.claude/scripts/ask-grok.sh   ...
~/.claude/scripts/ask-gemini.sh ...
```

| Флаг | Что делает |
|---|---|
| `-f` | файл или папка с материалами, можно несколько |
| `-s` | подмешать свой скилл Claude Code в задание как инструкцию |
| `-d` | рабочий каталог, он же **граница правок** |
| `-w` | разрешить менять файлы (**требует явного `-d`**) |
| `-e` | усилие рассуждения |
| `-m` | другая модель |
| `-t` | таймаут в секундах |

Примеры:

```bash
# мнение, только чтение
~/.claude/scripts/ask-codex.sh -e high "Найди, где эта функция сломается на пустом вводе: ..."

# разобрать папку с документами
~/.claude/scripts/ask-gemini.sh -f ~/Documents/проект -t 900 "Выпиши все файлы, где встречается X"

# делегировать правку, граница ровно эта папка
~/.claude/scripts/ask-grok.sh -w -d ~/Documents/проект/src -e high "Перепиши модуль на async"

# передать модели свой скилл как правила работы
~/.claude/scripts/ask-gemini.sh -s writing-style "Перепиши текст: ..."
```

## Модель безопасности

| | Codex | Grok | Antigravity |
|---|---|---|---|
| своя песочница уровня ОС | есть | есть | **нет** |
| чем закрыт | `--sandbox read-only` / `workspace-write` | `--sandbox read-only` / `workspace` | внешний Seatbelt-профиль `scripts/agy-sandbox.sb` |

У Antigravity собственной файловой границы нет. `--add-dir` только подсказывает контекст,
а его `--sandbox` ограничивает шелл и вдобавок отключается флагом
`--dangerously-skip-permissions`. Поэтому он запускается под `sandbox-exec`, и **этот
профиль остаётся единственной границей, страховки под ним нет.** Отсюда правило, которое
я вывел на своей шкуре: ничего в профиле не разрешать «на всякий случай».

Кроме записи профиль закрывает монтирование файловых систем (через него описан рабочий
побег из allow-default профиля), автозапуск `~/Library/LaunchAgents`, а также чтение
`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config` и токенов соседних CLI `~/.codex` и `~/.grok`.

Свой файл с доступами закрывается на уровне ядра одной переменной:

```bash
export ASK_SECRETS_FILE="$HOME/путь/к/файлу-с-доступами.md"
```

**Чего проект не делает.** Сеть у процессов открыта. Если во входных данных окажется
внедрённая инструкция, файловая граница от утечки не спасёт. Меня это смущает, но
закрывать сеть я пока не стал: для домашних задач овчинка не стоит выделки. Кому нужно -
смотрите [`sandbox-runtime`](https://github.com/anthropic-experimental/sandbox-runtime)
от Anthropic, он умеет allowlist по доменам.

## Обязательно прочитать

**[docs/pitfalls.md](docs/pitfalls.md)** - грабли, каждая из которых стоила отладки.
Почему `codex exec` виснет насмерть без одного перенаправления. Почему инструмент
возвращает «успех» при пустом результате. Как выходят из allow-default песочницы через
монтирование. Почему заявленный миллион токенов контекста у дешёвой модели не значит,
что она им пользуется.

## Что это не решает

Делегирование не даёт кода лучше, чем пишет сам Claude. На SWE-bench Pro впереди модели
Claude, а не эта тройка. Выигрыш тут в объёме, скорости и экономии контекста.

Задачи короче пятнадцати минут делегировать невыгодно. Запуск и последующая проверка
съедают всю экономию, а иногда и уходят в минус.

Отчёт модели о собственной работе ничего не доказывает. Проверять диффом и списком файлов
на диске: у меня Codex однажды бодро отрапортовал, что записал `файл.txt`, а на самом
деле создал `file.txt` латиницей. В инструкции субагентов эта проверка встроена.

## Матрица моделей ещё настраивается

Распределение «какая задача какой модели» в `skills/delegate/` - **рабочая гипотеза.**
Замеры взяты с независимого стенда, несколько клеток проверены живыми тестами, но
большинство пока опирается на бенчмарки, а не на практику. Где-то наверняка зову модель
тяжелее нужного, где-то экономлю там, где не стоило.

Это донастраивается по мере накопления опыта. Если возьмёте себе и увидите, что на ваших
задачах лучше работает другой расклад, так и должно быть. Правьте под себя: ценность
здесь в самом факте осознанного выбора, а таблица - дело наживное.

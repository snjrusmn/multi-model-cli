# multi-model-cli

Обвязка, которая подключает **Codex (OpenAI)**, **Grok Build (xAI)** и **Antigravity CLI
(Google)** к Claude Code как субагентов — и для второго мнения, и для делегирования
настоящей работы. Смысл в том, чтобы оплаченные подписки на эти сервисы не простаивали.

> Содержимое на русском: комментарии в коде, скиллы и документация.
> *Content is in Russian — code comments, skills and docs.*

Главное отличие от «просто вызвать CLI из скрипта» — **границы держит ядро, а не
обещания модели.** Без флага `-w` модель физически не может записать ни одного файла;
с `-w` правки возможны только внутри явно указанного каталога. Это проверено попытками
обойти запрет через инструмент правки, через шелл и через Python.

---

## Что внутри

```
scripts/     три обёртки с одинаковым интерфейсом + Seatbelt-профиль для Antigravity
agents/      определения субагентов Claude Code
skills/      delegate (делегирование работы) и second-opinion (второе мнение)
docs/        грабли, собранные при сборке — самое полезное здесь
```

## Требования

- **macOS.** Границы для Antigravity сделаны на Seatbelt (`sandbox-exec`), на Linux
  работать не будет без замены профиля.
- Штатный **bash 3.2** — код написан под него намеренно, без синтаксиса bash 4+.
- Установленные и авторизованные CLI (нужен не каждый, можно взять любой один):
  - [Codex](https://developers.openai.com/codex) — `npm i -g @openai/codex`
  - [Grok Build](https://x.ai/news/grok-build-cli) — `curl -fsSL https://x.ai/cli/install.sh | bash`
  - [Antigravity CLI](https://antigravity.google/docs/cli/overview/) — `curl -fsSL https://antigravity.google/cli/install.sh | bash`

## Установка

```bash
git clone https://github.com/USERNAME/multi-model-cli.git
cd multi-model-cli
./install.sh
```

`install.sh` делает симлинки в `~/.claude/{scripts,agents,skills}` и ничего не
перезаписывает молча — если файл уже есть, скажет и пропустит.

## Использование

Интерфейс у всех трёх одинаковый:

```bash
~/.claude/scripts/ask-codex.sh  [-e УСИЛИЕ] [-m МОДЕЛЬ] [-t СЕК] [-d DIR] [-f ПУТЬ]... [-s СКИЛЛ]... [-w] "промпт"
~/.claude/scripts/ask-grok.sh   ...
~/.claude/scripts/ask-gemini.sh ...
```

| Флаг | Что делает |
|---|---|
| `-f` | файл или папка с материалами, можно несколько |
| `-s` | подмешать свой скилл Claude Code в задание как инструкцию |
| `-d` | рабочий каталог — он же **граница правок** |
| `-w` | разрешить менять файлы (**требует явного `-d`**) |
| `-e` | усилие рассуждения |
| `-m` | другая модель |
| `-t` | таймаут в секундах |

Примеры:

```bash
# мнение, только чтение
~/.claude/scripts/ask-codex.sh -e high "Найди, где эта функция сломается на пустом вводе: ..."

# разобрать папку с документами
~/.claude/scripts/ask-gemini.sh -f ~/Documents/проект -t 900 "Выпиши все файлы, где встречается X"

# делегировать правку, граница — ровно эта папка
~/.claude/scripts/ask-grok.sh -w -d ~/Documents/проект/src -e high "Перепиши модуль на async"

# передать модели свой скилл как правила работы
~/.claude/scripts/ask-gemini.sh -s writing-style "Перепиши текст: ..."
```

## Модель безопасности

| | Codex | Grok | Antigravity |
|---|---|---|---|
| своя песочница уровня ОС | есть | есть | **нет** |
| чем закрыт | `--sandbox read-only` / `workspace-write` | `--sandbox read-only` / `workspace` | внешний Seatbelt-профиль `scripts/agy-sandbox.sb` |

У Antigravity собственной файловой границы нет: `--add-dir` — только подсказка контекста,
а его `--sandbox` ограничивает лишь шелл и вдобавок отключается флагом
`--dangerously-skip-permissions`. Поэтому он запускается под `sandbox-exec`, и **этот
профиль — единственная граница, страховки под ней нет.** Отсюда правило: ничего в
профиле не разрешать «на всякий случай».

Что закрыто в профиле, помимо записи: монтирование файловых систем (через него описан
рабочий побег из allow-default профиля), автозапуск `~/Library/LaunchAgents`, а также
чтение `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config` и токенов соседних CLI
`~/.codex` и `~/.grok`.

Свой файл с доступами можно закрыть на уровне ядра:

```bash
export ASK_SECRETS_FILE="$HOME/путь/к/файлу-с-доступами.md"
```

**Чего этот проект не делает:** сеть у процессов открыта. Файловая граница не защищает
от утечки, если во входных данных окажется внедрённая инструкция. Если это важно —
смотри [`sandbox-runtime`](https://github.com/anthropic-experimental/sandbox-runtime)
от Anthropic, он умеет allowlist по доменам.

## Обязательно прочитать

**[docs/pitfalls.md](docs/pitfalls.md)** — грабли, каждая из которых стоила отладки:
вечные зависания headless-режимов, инструменты, которые врут об успехе, дыры в
песочнице, лимиты моделей, которые не видны из документации.

## Что это не решает

- Делегирование не даёт кода лучше, чем пишет сам Claude. На SWE-bench Pro впереди
  модели Claude. Выигрыш здесь — объём, скорость и экономия контекста.
- Задачи короче примерно пятнадцати минут делегировать невыгодно: запуск и последующая
  проверка съедают выигрыш.
- Отчёт модели о собственной работе ничего не доказывает. Проверять диффом и списком
  файлов на диске — это встроено в инструкции субагентов.

## Матрица моделей ещё настраивается

Распределение «какая задача какой модели» в `skills/delegate/` — **рабочая гипотеза, а не
выверенный результат.** Оно собрано на независимых замерах и нескольких живых тестах, но
большинство клеток пока опираются на бенчмарки, а не на нашу собственную практику.
Наверняка что-то распределено неоптимально: где-то зовём модель тяжелее, чем нужно,
где-то наоборот экономим там, где не стоило.

Это продолжает донастраиваться по мере накопления опыта. Если возьмёшь себе и увидишь,
что на твоих задачах лучше работает другой расклад — так и должно быть, правь под себя.
Ценность здесь не в конкретных клетках таблицы, а в том, что выбор вообще стал
осознанным решением, а не случайностью.
